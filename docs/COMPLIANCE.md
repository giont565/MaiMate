# MaiMate 法規檢討（Compliance Review）

> 版本：2026-07-19｜隊伍內部文件
> ⚠️ 本文件是工程團隊的法規風險自查，**不是法律意見**。商業化前應諮詢執業律師／MaiCoin 法遵部門。
> 台灣虛擬資產專法立法進行中，以下依現行法規與金管會指導原則整理，決賽前建議再確認最新動態。

## 結論先講

**競賽期間的 Demo 本身沒有違法疑慮**（用自己的帳戶、自己的錢、最小額度、經 KYC 的合規交易所）。
產品設計的四條紅線（不報明牌、不代操、不碰保管、不碰提領）正好對應四個主要法規風險——
這不是巧合，**上台要把這個對應關係講出來**，它就是法遵敘事。

## A. 競賽期間本身的合規性

| 項目 | 狀態 | 依據/說明 |
|---|---|---|
| Demo 實際下單 | ✅ 合規 | 用隊員本人 MAX 帳戶（已 KYC）、本人資金、最小額度。本人在合規交易所下自己的單，無任何執照問題 |
| 官方 CSV 使用 | ✅ 合規（有條件） | 主辦信件明示「僅供競賽提案與開發使用，勿轉傳公開」→ 不進 git、不公開、只放 Drive/S3 |
| 工作坊資料入 RAG | ✅ 合規（有條件） | 同上「供提案發想與實作開發之參考」→ 競賽用途 OK；語料不進 git、Demo 不展示原始簡報內容、決賽後刪除 |
| MAX API 使用 | ✅ 合規 | 官方開放給參賽者；遵守 rate limit；API Key 本人申請本人用 |
| Kiro/AWS 兌換碼 | ✅ 合規 | 僅限本人使用（主辦明文，違者取消資格）——已寫入團隊紅線 |
| 模擬資料隱私 | ✅ 無虞 | 官方 CSV 為模擬帳戶資料，非真實個資 |

## B. 產品設計的監管風險與對應設計

### B1. 投資顧問／招攬疑慮 → 「不報明牌」

- **風險**：若 AI 主動推薦特定幣種買賣、暗示漲跌、或以「保證獲利」話術招攬，可能觸及
  投資建議監管疑慮（虛擬資產雖非有價證券，證投顧法原則不直接適用，但金管會對 VASP
  的廣告招攬有規範：**不得誇大不實、不得保證獲利**；若涉及具證券性質之虛擬資產（STO）則直接落入證交法/證投顧法範圍）
- **對應設計**：
  - System prompt 紅線＋程式層正則攔截（「建議買進」「保證獲利」「一定漲」句式）＋ Bedrock Guardrails，三層
  - AI 輸出僅限：事實呈現、個人歷史脈絡、多方案比較（含風險與費用）——**選擇權永遠在使用者**
  - 幣種池僅主流幣（BTC/ETH/SOL/DOGE/USDT/USDC），不涉 STO

### B2. 全權委託／代客操作疑慮 → 「不代操」

- **風險**：AI 自動執行交易若無使用者逐筆授權，形同全權委託代操——這在證券期貨領域是
  特許業務，虛擬資產領域目前無此執照類別，做了就是無照經營灰區
- **對應設計**：
  - **逐筆二次確認是硬架構not UI 裝飾**：`execute_order` 不在 LLM 工具清單，AI 技術上無法自行下單
  - 確認憑證 60 秒過期、單次有效，杜絕「預先授權一批」的變形
  - Audit Log 完整留痕，可證明每筆交易皆有使用者明確確認

### B3. 資產保管／洗錢防制 → 「不碰保管、不碰提領」

- **風險**：涉及代收付、保管、移轉虛擬資產即落入洗錢防制法之虛擬資產服務業（VASP）
  登記義務範圍
- **對應設計**：
  - MaiMate **不持有、不經手任何資產**——資產始終在使用者自己的 MAX 帳戶（MAX 已完成金管會洗錢防制登記）
  - API Key 權限**強制不開提領**，連技術上都做不到移轉
  - 定位為「嵌入 MaiCoin/MAX 的互動層」：商業化時法遵主體是 MaiCoin（已具 VASP 資格），MaiMate 不獨立成為 VASP

### B4. 個人資料保護（個資法）

- **風險**：正式產品將處理使用者交易紀錄（個資），須符合個資法之告知、同意、目的限制
- **對應設計**：
  - 競賽階段用官方模擬資料，無真實個資
  - 架構已內建：輸入 PII 清洗（身分證/手機/卡號不進模型）、資料不出 AWS 帳號、Audit Log 不記原文只記摘要
  - 商業化前提：隱私權政策、使用者同意機制、（若用境外模型區域）跨境傳輸告知——列入 roadmap 非 P0

### B5. 金管會「金融業運用 AI」指導原則對齊

金管會 2024 發布金融業運用 AI 指引，六大核心原則我們逐條有對應：

| 指引原則 | MaiMate 對應 |
|---|---|
| 建立治理及問責機制 | Audit Log 全程留痕、人類最終確認 |
| 重視公平性及以人為本 | 三模式提醒強度、決策權在人 |
| 保護隱私及客戶權益 | PII 清洗、不報明牌、風險充分揭露 |
| 確保系統穩健與安全 | 雙層護欄、離線備援、金鑰管理 |
| 落實透明性與可解釋性 | 確定性計算＋每個結論附數據來源、工具呼叫可視化 |
| 促進永續發展 | 教育陪伴定位、防詐內容 |

**這張表可以直接放進簡報**——評審是金融業，對這個指引熟。

### B6. 防詐相關（加分不是風險）

165 反詐與金管會防詐宣導為公開資訊，入 RAG 無授權問題；AI 主動辨識詐騙話術
（「保證獲利」「老師帶單」）屬正面設計，與政策方向一致。

## C. 商業化前提（P2，誠實列出）

1. 以 MaiCoin 內建功能形式上線 → 法遵掛 MaiCoin 既有框架（最可行，也是產品定位）
2. 虛擬資產專法通過後，依新法確認「AI 輔助交易介面」是否有新增義務
3. 個資法完整合規（隱私政策、同意、DPIA）
4. 廣告與行銷素材事前法遵審查（不得涉招攬、保證收益）

> 不碰保管是 API 權限層面做不到提領、可問責是全程 Audit Log——**合規不是我們簡報的免責聲明，是我們的系統設計。**」
